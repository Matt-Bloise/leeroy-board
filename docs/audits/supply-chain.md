## Fixed in this branch (`cloud/supply-chain`)

- `persist-credentials: false` on every `actions/checkout` step. The first run set it on the 19 steps that lacked it; the re-check on 2026-11-22 found 7 more on current master and set it there too: `nightly-production.yml` (1), `preview-tests.yml` (3), `security.yml` (1), and the two workflows added since, `pages-prune.yml` and `roster-upsert.yml` (1 each). The other 2 (`flake-rerun.yml`, `security.yml`) already set it, so all 28 checkout steps now do. Reasoning: checkout otherwise leaves the job's `GITHUB_TOKEN` in `.git/config` for every later step, including steps that run PR-controlled code (`npm ci`, tests) and the deploy job. No workflow step runs `git fetch/push/pull/commit` (grepped again on 2026-11-22; the `gh` calls authenticate with `GH_TOKEN`/`GITHUB_TOKEN` env, not git config), so behaviour is unchanged. All workflow YAML parses; actionlint 1.7.7 reports nothing on master or on this branch (run without its shellcheck and pyflakes integrations); `node --test "tests/unit/*.test.mjs"` passes.

## Checked and fine

- **Action pinning:** every `uses:` is pinned by full SHA with a version comment: `actions/checkout` 11bd719 (v4.2.2), `setup-node` 39370e3 (v4.1.0), `upload-artifact` b4b15b8 (v4.4.3), `download-artifact` fa0a91b (v4.1.8), `github-script` 60a0d83 (v7.0.1), `actions/cache` 1bd1e32 (v4.2.0, new since the first run, in the `preview-tests.yml` browser job), `codeql-action/upload-sarif` f09c1c0 (v3.27.5). The first-party SHAs are consistent across all workflows and match the pins documented in `preview-tests.yml:26-30`. Only `actions/*` and `github/*` are used; no other publishers.
- **`pull_request_target`:** not used. `workflow_run` is used once (`flake-rerun.yml`); it checks out the default branch with `persist-credentials: false`, is limited to same-repo `pull_request` failures, and does not run PR code.
- **Fork PRs:** preview and spin-up jobs require `head.repo.full_name == github.repository`; forks only run the policy step and get no secrets under `pull_request`.
- **Production deploy:** triggered by a push to master (with `paths-ignore`) or `workflow_dispatch`, guarded by `if: github.ref == 'refs/heads/master'` (`deploy-cloudflare.yml:81`), `environment: production` (line 84), `contents: read` (line 70). The Cloudflare token is not written to Worker secrets (comment at `deploy-cloudflare.yml:425`; enforced by `tests/unit/workflow-secrets.test.mjs`), and Worker secrets come only from the deploy job. The token is exported via `GITHUB_ENV` (line 214), which is masked in logs.
- **Artifacts:** logs and reports only, kept 14 days (30 days for the Semgrep, ZAP and cross-engine reports); no credentials uploaded (paths are log/report files). `download-artifact` reads `preview-test-logs-*` in the same run only.
- **Lockfiles:** `npm ci` everywhere; both lockfiles have integrity hashes and no non-registry sources. `wrangler` is exactly pinned.
- **Secret history scan:** re-run on 2026-11-22 over the added lines of `git log --all -p` (1,378 commits on all refs fetched here) for AWS, GitHub, Anthropic/OpenAI/Groq/Cerebras/Google keys, Slack, Discord webhook/bot token, JWT and private-key blocks. Every hit sits in a unit test that uses it as a made-up fixture: `sk-ant-` strings (`tests/unit/ai-keys-evasion.test.mjs`, `ai-keys-env-secret.test.mjs`, `ask-real-names.test.mjs`, `measure-research-tools.test.mjs`, `voice-eval-runner.test.mjs`) and sample AWS, Slack, JWT and private-key markers (`group-memory-hardening.test.mjs`, `ask-real-names-fixes.test.mjs`). They were judged from test context only, not checked against any provider. No `.env`, `.pem`, `.dev.vars` or key files are tracked.
