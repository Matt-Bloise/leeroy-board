### F04. Q01 as written takes the five friends offline and orphans their saved state. BLOCKER (reliability, privacy). Confirmed mechanism.
Evidence: `lb:infrastructure/worker/auth.js:15` `sha256Hex(\`${env.KEY_SALT}:${key}\`)`; `lb:infrastructure/worker/account.js:39` `userKey = sha256Hex(\`${env.USER_SALT}:user:${discordId}\`)`; `sessions.user_key` and `user_state.user_key` are that hash (`lb:infrastructure/schema.sql:159-176`). Deploy order in `lb:.github/workflows/deploy-cloudflare.yml`: step 226 "Deploy Cloudflare Worker" runs before step 248 "Sync Worker Secrets", and the secrets loop skips empty values silently (`:262-266`).
Consequences of Q01 "remove from vars; add as secrets; rotate; re-key": (1) the first deploy runs with no salt until the secrets step completes; `auth.js:40` returns `{configured:false}` and `account.js:81` answers 500 for every login in that window; if the GitHub secret was never created the outage is permanent and CI stays green. (2) Rotating `KEY_SALT` invalidates all five member keys at once; "a friend's new key works on production" is the oracle, so the five are locked out until someone hands them new keys by hand. (3) Rotating `USER_SALT` orphans every `sessions` and `user_state` row: prefs silently lost, and the orphans can never be erased by their owner (`DELETE /me` keys on the new hash), which is a privacy regression the plan does not mention. (4) `guest_rate_limits` keys reset (harmless).
Change: split Q01. Q01a (risk 7): move both salts to secrets with the **same values**, and reorder the deploy workflow so "Sync Worker Secrets" runs before "Deploy" and fails the job when `KEY_SALT` or `USER_SALT` is empty. Zero user impact. Q01b (risk 9, runs alone, after Q18/Q26 retire member keys): rotation with dual salts (`KEY_SALT_PREV`, `USER_SALT_PREV`) read for 30 days, a re-hash on next successful login for `user_state`, and only then drop the old. The claim in SYNTHESIS 1.14 that hashes "rest on" public salts is right, but the exposure is a dictionary attack on a leaked `members` table of five 22+ char random keys; low urgency, so Q01b is not Wave 1.
